import InfoBox from "./InfoBox";

<InfoBox>
  <h3>COCO Detection Summary (Object Detection)</h3>

  <p>
    This widget shows how a model's detection quality changes across severity levels
    for each specified corruption algorithm, using the standard COCO evaluation protocol.
  </p>

  <p>
    For each corruption algorithm, three tables are displayed side by side across severities:
    a COCO AP/AR table, an F-Beta Summary table, and a Best F-Beta Operating Points table.
    The first severity column (typically "None") is the clean-data baseline; all subsequent
    columns reflect progressively harder corruptions of the same data.
  </p>
</InfoBox>

<InfoBox>
  <h4><b>How to read?</b></h4>

  <p>
    Each row in a table is a single metric; each column is a severity level. Values are
    shown as percentages, except for confidence threshold, which is a raw decimal between
    0 and 1. The small coloured delta beneath each non-baseline value shows the change
    from baseline in percentage points — green indicates improvement, red indicates
    degradation, and neutral indicates a negligible shift (&lt;0.5pp).
  </p>

  <p>The three tables each answer a different question:</p>
  <ul>
    <li>
      <b>COCO AP/AR</b> — the broadest signal. <b>AP@.50</b> reflects basic localisation
      quality; <b>AP@.10:.95</b> additionally penalises imprecise boxes; the
      <b> small / medium / large</b> breakdowns reveal whether degradation is concentrated
      on a particular object size
    </li>
    <li>
      <b>F-Beta Summary</b> — reflects the balance between precision and recall at fixed
      IoU thresholds. <b>F1</b> weights precision and recall equally; <b>F2</b> up-weights
      recall, making it more sensitive to missed detections
    </li>
    <li>
      <b>Best F-Beta Operating Points</b> — shows the best achievable F-score at each
      severity and the confidence threshold at which it was found, alongside the
      corresponding precision and recall at that point
    </li>
  </ul>

  <p>
    Scan <b>horizontally</b> across a row to see how a metric degrades as severity
    increases. Scan <b>vertically</b> down a column to identify which metric types are
    most affected at a given severity level.
  </p>
</InfoBox>

<InfoBox>
  <h4><b>Interpretation</b></h4>

  <p>
    A robust model shows small, consistent deltas across all rows as severity increases.
    If most deltas are near zero and no single metric collapses while others hold, the
    model can be considered robust to the given corruption and no further action is required.
  </p>

  <p>When degradation is present, the pattern of decline indicates where the problem lies:</p>
  <ul>
    <li>
      <b>AP@.50 stable but AP@.10:.95 dropping</b> — the model is still finding objects
      but box localisation is being disrupted; consider fine-tuning with tighter IoU criteria
    </li>
    <li>
      <b>Small-object AP degrading faster than medium / large</b> — the corruption is
      disproportionately affecting small instances; targeted augmentation at those scales
      is recommended
    </li>
    <li>
      <b>F2 degrading faster than F1</b> — recall is falling more than precision, meaning
      the model is missing more objects than it is generating spurious ones; retraining
      with additional samples under this corruption type is advised
    </li>
    <li>
      <b>Confidence threshold shifting substantially upward at higher severities</b> — the
      model is becoming less calibrated; a much stricter confidence threshold is needed to
      maintain the same precision/recall balance, which may indicate that deployment
      thresholds need recalibrating per operating condition
    </li>
  </ul>

  <p>In cases of significant degradation, consider:</p>
  <ul>
    <li>Retraining with additional samples augmented using the observed corruption type</li>
    <li>Reviewing confidence thresholds — some degradation in F-score may be recoverable by tuning rather than retraining</li>
    <li>Reviewing model architecture if degradation is severe and consistent across all metric types</li>
  </ul>

  <p>
    If metrics improve as severity increases, this may indicate the model has overfitted to
    this corruption type during training. In that case, retraining with fewer augmented
    samples of this type is recommended.
  </p>
</InfoBox>
