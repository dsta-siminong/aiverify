import InfoBox from "./InfoBox";

<InfoBox>
  <h3>Confusion Matrix Statistics</h3>

  <span>
    This widget shows how a model's predictions across all classes change 
    as image perturbations increase.
  </span>

  <span>
    For each specified corruption algorithm and severity level, a confusion 
    matrix is displayed, summarizing the model's predictions for every class.
  </span>
</InfoBox>

<InfoBox>
  <h4>
    <b>How to read?</b>
  </h4>

  <p>
    For each corruption algorithm and severity level, a full N × N confusion
    matrix is shown (where N is the number of classes).
  </p>

  <p>
    In the matrix:
  </p>

  <ul>
    <li>Each row represents the true class of the image</li>
    <li>Each column represents the class predicted by the model</li>
    <li>Values along the main diagonal correspond to correct predictions</li>
    <li>Values outside the diagonal correspond to misclassifications</li>
  </ul>

  <p>
    These matrices help identify which classes are being confused with one
    another and whether corruption introduces systematic misclassification
    patterns (for example, Class X increasingly being predicted as Class Y as
    corruption severity increases).
  </p>
</InfoBox>

<InfoBox>
  <span>
    <b>Interpretation</b>
  </span>

  <span>
    The confusion matrix helps identify which classes the model tends to confuse
    with one another under a given corruption and severity level.
  </span>

  <span>
    Ideally, most predictions should lie along the main diagonal of the matrix,
    indicating that the predicted class matches the true class. As corruption
    severity increases, it is expected that some predictions move away from the
    diagonal, resulting in more misclassifications.
  </span>

  <span>
    If the same off-diagonal patterns repeatedly appear (for example, Class X is
    frequently predicted as Class Y), this may indicate:
  </span>

  <span>
    <ul>
      <li>Visual similarity between the affected classes</li>
      <li>Insufficient or unrepresentative training samples</li>
      <li>Model reliance on features that are sensitive to the applied corruption</li>
    </ul>
  </span>

  <span>
    In such cases, consider:
  </span>

  <span>
    <ul>
      <li>Adding more diverse training samples for the affected classes</li>
      <li>Including augmented examples that resemble the observed corruption</li>
      <li>Improving class separation through feature engineering or model architecture changes</li>
      <li>Reviewing class balance within the dataset</li>
    </ul>
  </span>

  <span>
    If the confusion matrix remains largely unchanged across corruption severities,
    the model can be considered robust to the given perturbation.
  </span>
</InfoBox>
